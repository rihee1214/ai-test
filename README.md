# 영화제 편성 앱 실험 결과

같은 영화제 편성 앱을 네 조건에서 만들어 Plan 모드와 스킬 사용 여부에 따른 품질, 작업 시간, 토큰 사용량을 비교했다. 1차 과제는 편성 앱 구현, 2차 과제는 직전 발행본을 초안으로 복구하는 기능 추가였다.

**시간과 토큰은 C가 가장 적었다. 직접 사용해 본 결과 운영 담당자 화면은 D가, 두 상영관의 일정을 비교하는 관객 시간표는 B가 가장 좋았다.**

## 작업 시간과 토큰

단계별 수치는 분:초 / 토큰이다. 구현과 자체 검증을 포함하며, 계획 승인 대기와 두 단계 사이의 휴지 시간은 제외했다.

| 조건 | 계획 | 1차 구현·검증 | 2차 변경·검증 | 총 작업 시간 | 총 토큰 |
|---|---:|---:|---:|---:|---:|
| A · 일반 / 스킬 OFF | — | 4:56 / 458,796 | 1:48 / 202,152 | 6:44 | 660,948 |
| B 재실행 · Plan / 스킬 OFF | 0:32 / 52,897 | 5:35 / 561,031 | 2:35 / 610,317 | 8:49 | 1,224,245 |
| C · 일반 / 스킬 ON | — | 3:52 / 352,617 | 1:44 / 256,592 | 5:36 | 609,209 |
| D · Plan / 스킬 ON | 0:47 / 92,147 | 5:59 / 981,278 | 2:22 / 563,945 | 9:08 | 1,637,370 |

최초 B는 계획을 `medium`으로 작성한 뒤 1차 구현을 `max`로 완료했다. 전체 25분 2초와 2,301,509토큰이 들었으며, 추론 강도가 달라 비용 비교에서 제외했다. 재실행 B에서는 `max` 턴을 7초 만에 중단했고 기록된 토큰 증가량은 0이었다. 표의 총 시간에는 이 7초가 포함된다. 재실행 B의 계획과 두 차례의 완료된 구현은 모두 `medium`이었다.

Plan을 사용한 조건의 총 토큰은 스킬 OFF에서 1.85배(B/A), 스킬 ON에서 2.69배(D/C)였다. 계획 작성 자체는 각각 32초와 47초였다. OFF 조건에서는 2차 변경에서, ON 조건에서는 1차 구현에서 토큰 차이가 가장 컸다.

## 직접 사용하며 확인한 차이

| 업무 | 관찰 결과 |
|---|---|
| 다음 작품을 넣을 시간 찾기 | 상영 후 10분 정리는 공통 요구사항이었지만, 그 시간을 화면에 어떻게 표현할지는 지정하지 않았다. B와 D는 상영 시간을 범위로 보여 주고 정리 시간도 표시해 다음 편성이 가능한 시각을 읽기 쉬웠다. |
| 편성 작업 이어가기 | B와 D 모두 별도 메뉴가 필요하지 않은 조작을 모달로 열었다. 담당자가 보던 시간표를 떠나 다른 화면을 오가는 일이 줄었다. |
| 상영관 사용 중단 해제 | D에서는 중단 구간이 명확히 보였고 담당자가 해제할 수 있었다. B는 사유를 입력받은 뒤 다시 보여 주지 않았고 중단 구간을 삭제할 수도 없었다. D에서도 사유 자체를 확인하기는 어려웠다. 운영자 평가를 가른 것은 상황이 바뀌었을 때 중단을 해제할 수 있느냐였다. |
| 관객이 두 관의 일정 비교하기 | 관객 시간표의 배치와 가독성은 B가 더 좋았다. 최초 B와 재실행 B를 모두 직접 평가했고 판단은 같았다. 이 장점은 `medium`으로 구현한 재실행에서도 확인됐다. |
| 디자인과 문구 | 전반적인 디자인은 스킬을 사용한 결과물을 선호했다. 문구도 D가 조금 더 자연스럽게 느껴졌지만, 글쓰기 스킬의 효과를 판단할 만큼 사례가 충분하지 않았다. |

## 다음 개발에 적용할 점

1. **규칙과 사용자 역할이 얽힌 작업에는 Plan을 쓰겠다.** 이번에는 토큰이 더 들었지만, 내가 정한 운영 규칙을 사용자가 화면에서 어떻게 이해하고 행동할지까지 챙긴 점이 유용했다. 10분 정리 시간의 표현이 대표적인 사례다.
2. **스킬의 가치는 실제 업무를 끝까지 해 보고 판단하겠다.** D의 장점은 중단을 등록하는 순간보다 나중에 다시 해제하려 할 때 분명해졌다. 스킬 ON 결과에서 이런 세부 동작과 디자인을 선호했지만, 개발 중 발견된 버그 수는 측정하지 않았다.
3. **제품을 이어 만든다면 D의 운영 화면에 B의 관객 시간표를 결합하겠다.** 담당자에게 중요한 일은 편성을 수정하고 되돌리는 것이고, 관객에게 중요한 일은 두 관의 일정을 빠르게 비교하는 것이었다.

최종 비교는 조건당 한 실행의 로그와 사용자의 직접 평가에 근거한다. 특정 스킬이 어느 기능을 만들었는지, 다른 과제에서도 같은 토큰 차이가 날지는 이번 결과만으로 판단하기 어렵다.
