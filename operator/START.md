**첫 실행은 D:\ai-test\367 폴더만 프로젝트로 열고 새 세션에서 시작한다.** 번호는 익명 ID다. 프로세스·스킬 설정이 전역일 수 있으므로 한 번에 하나만 진행한다. 이 문서는 진행자용이다.

준비 단계에서 PowerShell Get-Random으로 조건과 번호를 각각 한 번 비복원 추첨했다. 이 순서를 유지한다. 네 클론은 같은 기준 커밋에서 독립적으로 생성했고 기준본은 base/에 있다. operator/는 진행자 자료와 원본 기록, grading/은 익명 채점용 사본을 두는 위치다. 세션에는 자기 번호 폴더와 해당 txt의 본문만 제공한다. 진행자 폴더와 다른 실행의 자료는 열어 주지 않는다.

## 과제 선정과 시간

소규모 교육센터의 키트 배정은 클릭할 때마다 잔량·행 상태·인계 목록이 함께 바뀐다. 세 신청으로 정상 성공, 부족, 잔량과 요청량이 같은 경우, 취소, 복원을 구분할 수 있다. 담당자가 포장할 곳과 수량을 얻었는지도 관찰할 수 있다. 제품 기획·범위와 예시 데이터는 base/TASK.md와 base/public/seed.json에 있다.

**상한은 45분**이다. 한 화면, 세 신청, 두 업무 상태이며 서버와 고정 데이터가 제공된다. 패키지 설치, DB 구축, 인증, 배포가 없어 계획부터 검증까지 시도할 수 있는 범위다. 45분은 사전에 정한 상한이며 실제 완주 시간은 실행에서 측정한다.

## 시작 직전

- [ ] [환경표](ENVIRONMENT.md)의 ON/OFF 사전 대조를 마치고 첫 실행 전에 묶음·도구·권한 차이를 고정했다.
- [ ] 해당 폴더에서 `git rev-parse HEAD`가 `2f464abb38c74bd7c8e1cd566aac74c40115f1cd`이고 `git status --porcelain --untracked-files=all`이 비어 있다.
- [ ] 각 프로젝트의 Git 루트는 자기 번호 폴더다. 모델·추론 강도·권한·Auto-review와 공통 지침을 대조했다.
- [ ] 조건에 맞게 설정한 후 새 세션을 열고 첫 모드 및 실제 사용 가능 목록을 확인했다. 다른 실행을 요약한 메모리나 이전 대화가 연결되지 않는다.
- [ ] 이전 서버가 종료됐고 4173 포트를 쓸 수 있다. 빈 전용 Edge 프로필, 960×640 콘텐츠 뷰포트, 100% 확대율을 준비했다.
- [ ] [실행 기록지](RUN.md)를 operator/records/ 아래에 ID별로 복사하고 타이머와 결과 보존 위치를 준비했다. 첫 txt 본문을 전송하는 순간 계측을 시작한다.

## 응답 규칙

Plan 조건은 계획을 받은 후 같은 세션을 구현 가능한 모드로 바꾸고 [승인 문구](prompts/approval.txt)만 보낸다. 일반 조건에서 자발적 계획 승인을 요청해도 같은 문구를 쓴다. 계획만 작성하고 승인을 묻지 않으면 자발적 작성으로 기록한다. 예정된 승인, 자발적 승인, 수동 권한 승인, 기타 질문을 따로 센다.

사실 질문은 공통 자료의 문구로 답한다. 구현 결정은 “공통 과제 자료의 요구사항을 충족하는 범위에서 결정해 주세요.”라고 답한다. 사람의 새 요구, 설계 조언, 오류 힌트는 시각과 원문을 별도 개입으로 기록한다.

## 시간·사용량과 종료

첫 프롬프트부터 구현과 자체 검증을 마쳤다는 최초 보고 또는 판정 시간 45:00 중 먼저 발생한 순간까지 잰다. 계획 제출은 단계 경계다. 총경과에서 사람의 응답 때문에 모든 작업이 멈춘 구간의 합집합만 뺀다. 질문 뒤 다른 도구나 하위 작업이 진행되면 그 시간은 포함한다. 멈춤을 관찰할 수 없으면 차감하지 않고 메모한다. 계획·도구 실행·자동 심사 대기는 상한과 전체 비용에 포함한다.

단계별 누적 사용량이 보이면 같은 계수기의 차이로 계획과 구현을 나눈다. 입력·출력·캐시·추론·하위 작업 포함 범위와 출처를 기록한다. 중복 합산하지 않는다. 자동 심사 비용과 대기도 분리해 보일 때 기록한다. 일부만 보이면 ‘부분 측정’, 전혀 보이지 않으면 ‘측정 불가’다. 호출·승인 횟수는 전체 기록을 확인했을 때만 0으로 기록한다.

## 최초 결과 보존과 채점

1. 종료 순간 시각과 마지막 상태를 기록한다. 상한이면 에이전트와 진행 중인 쓰기 작업을 즉시 중지한다. 추가 수정이나 초기화 전에 화면, 최종 보고, 자체 검증 출력, 사용량과 사건 기록을 보관한다. 보고가 없으면 ‘결과 없음’이라고 쓴다.
2. operator/records/<ID>/first/에 작업 폴더 전체(숨김 파일과 .git 포함)를 복사한다. `git worktree list --porcelain`로 추가 작업 위치를 확인해 해당 작업 트리와 실행에 필요한 데이터도 복사한다. HEAD와 `git status --porcelain --untracked-files=all`을 함께 저장한다. 커밋·diff만으로 대체하면 신규 파일이 빠질 수 있다. 전용 브라우저의 해당 출처 데이터 또는 프로필 사본과 종료 당시 화면을 함께 저장한다.
3. 최초 보존본을 보관하고 grading/<ID>/에 익명 실행 사본을 만든다. 실제 구현된 작업 트리를 사용하고 실행 필수 파일을 빠짐없이 포함한다. 대화, 평가 기록, 스킬 로그와 Git 메타데이터는 채점자에게 제공하지 않는다. 빈 프로필에서 루트의 `node serve.mjs`로 시작한다. 채점 순서는 214, 367, 581, 796이다.
4. [100점 평가표](RUBRIC.md)를 사본별로 작성하고 점수를 확정한 뒤 조건과 연결한다. 진행자가 채점도 맡으면 비맹검이라고 표시한다. 미완성 실행도 관찰된 점수를 인정한다. 이후 변경은 별도 수정 사본에서만 수행해 [비교·수정 기록](RESULTS.md)에 남긴다.
