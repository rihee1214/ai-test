# 영화제 실험 진행 카드

## 공통 실행

새 기준 저장소에 PROJECT.md와 동일한 최소 실행 환경만 둔다. 이 디렉터리는 진행자 전용이다. SCORE.md, CHANGE.txt, 비교 조건, 이전 실험 자료는 복제본에 넣지 않는다. 기준 커밋에서 독립 클론 네 개를 만들고 하나씩 별도 프로젝트로 연다. 기존 키트 폴더는 재사용하지 않는다. 네 실행 순서와 익명 ID를 시작 전에 새로 추첨한다.

각 조건의 전체 상한은 **75분**이다. 본 과제 45분, 변경 요청 30분으로 고정한다. 각 단계에서 구현·자체 검증의 최초 완료 보고 또는 단계 상한 중 이른 시점에 당시 코드와 로그를 별도 보존한다. 일찍 끝난 단계의 잔여 시간은 이월하지 않는다. 1단계가 미완성이어도 그 시점의 상태를 보존하고 같은 세션에서 변경 요청으로 넘어간다. 2단계는 네 조건 모두 일반 모드로 시작하며 스킬 가용성은 유지한다. 따라서 Plan 요인은 첫 과제를 시작한 모드다. 2단계 요청 전의 진행자 준비 시간은 비용과 별도 기록한다.

|조건|첫 모드|대상 묶음|첫 본문|
|---|---|---|---|
|A|일반|OFF|아래 일반 본문|
|B|Plan|OFF|아래 Plan 본문|
|C|일반|ON|아래 일반 본문|
|D|Plan|ON|아래 Plan 본문|

**일반 본문**

```text
PROJECT.md에 설명된 작은 영화제의 하루를 만들어 주세요. 지금 구현과 자체 검증을 진행해 주세요. 완료하면 실행 방법과 실제 확인한 결과를 알려 주세요.
```

**Plan 본문**

```text
PROJECT.md에 설명된 작은 영화제의 하루를 만들어 주세요. 먼저 계획을 제시하고, 승인 후 구현과 자체 검증을 진행해 주세요. 완료하면 실행 방법과 실제 확인한 결과를 알려 주세요.
```

계획 승인 때는 모드를 일반으로 돌리고 “제시한 계획대로 구현과 자체 검증을 진행해 주세요.”를 보낸다. 일반 모드의 자발적 승인에도 같은 문구를 사용한다. 두 번째 본문은 네 세션 모두 CHANGE.txt 전문이다.

## 스킬 통제

1. 지정 묶음은 기존의 Superpowers 7.0.1 전체 15개와 Computer Use 26.1117.31558의 computer-use 한 개다. 기본 스킬, 브라우저 접근권, 나머지 플러그인, 공통 지침, 모델·추론 강도, Auto-review와 권한은 동일하게 둔다.
2. ON은 동일한 16개가 새 실행 세션에 노출되는 상태다. 사용 지시는 하지 않는다. OFF는 설정에서 Superpowers 플러그인을 비활성화하고 Computer Use 스킬 단독 비활성화를 우선 적용한다. 단독 설정이 반영되지 않으면 두 OFF 모두 해당 플러그인 전체를 끄고 동반 도구·훅 차이를 첫 실행 전에 기록한다. 기기 전체 설정을 바꾼다면 이전 세션을 닫고 순차 실행한다.
3. CLI를 쓴다면 네 실행 모두 같은 CLI로 통일한다. 설치본 도움말에서 -C, --no-daemon, --approve-for-me를 확인했다. 예: codex --no-daemon --approve-for-me -C "D:\실험\실행ID". 실제 경로로 바꾼다. 새 세션에서 /skills를 열어 검색만 하고 선택하지 않는다. ON 16개, OFF 0개와 해당 cwd를 캡처한다. 포그라운드에서 확인할 수 없으면 같은 설정의 app-server skills/list에 대상 cwds와 forceReload를 주어 실효 목록을 조회하고 첫 턴의 제공 목록도 대조한다. 목록을 확인할 수 없거나 조건과 다르면 해당 실행은 보류한다.
4. **파일을 직접 읽는 것까지 차단해야 할 때**는 같은 OS 스냅샷의 격리 VM 두 개를 사용한다. OFF 이미지에서만 대상 패키지·캐시·별칭 및 사용자·프로젝트의 중복 스킬 사본을 제거하거나 실행 계정에 읽기 거부를 적용한다. 두 이미지 모두 네트워크 및 호스트 공유 폴더를 같은 방식으로 제한한다(모델 서비스 연결은 동일하게 허용). 진행자·다른 실행 자료도 공유하지 않는다. OFF에서 설치 당시 확인한 실제 경로와 별칭을 실행 계정으로 열어 ‘없음/접근 거부’를, ON은 같은 파일의 읽기 성공을 점검한 후 새 세션 목록을 검증한다. 호스트의 기존 설치본은 보존한다. UI 비활성화만 적용한 실행은 ‘목록 비노출 검증’으로 표기한다.
5. 첫 프롬프트, 실제 첫 모드, 승인 시각, 첫 턴에서 모델에 제공된 목록과 도구를 기록한다. 설정에만 보이는 목록과 처음 제공된 목록이 다르면 조건 이탈로 분리한다. ON의 사용 가능과 실제 호출은 별개다. 호출 확인 / 전체 기록에서 호출 없음 / 확인 불가를 나눠 적는다. OFF에서 대상 사용이 확인되면 원래 조건의 비교 결과에 합산하지 않는다.
